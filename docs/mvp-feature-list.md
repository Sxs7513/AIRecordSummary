# AI 录音检索产品 MVP 功能清单

## 1. 文档目的

本文档用于定义产品第一阶段 MVP 的功能边界、优先级、验收口径和暂不纳入范围的内容，确保后续技术设计和开发都围绕核心价值展开。

MVP 的目标不是做一个万能 AI Agent，而是先验证以下核心价值：

- 用户可以把历史录音资产沉淀为可搜索的知识库。
- 用户可以用自然语言快速找回录音中的细节。
- 用户可以基于命中的原始内容获得可信的总结答案。
- 用户可以从答案追溯回具体录音和时间点。
- 用户可以区分同一条录音中的不同说话人，并识别出重点目标人物。

## 2. 目标用户与核心场景

### 2.1 目标用户

- 有大量历史录音、会议音频、采访录音、课程录音的个人用户
- 需要回查历史讨论细节的小团队
- 对录音内容检索和知识沉淀有持续需求的内容工作者

### 2.2 核心场景

- 搜索某个观点、结论、承诺、预算、日期或人名曾在哪次录音中出现过
- 在多条历史录音中查询某个主题被讨论过哪些内容
- 判断某个已知的重要人物是否出现在录音中，以及他说了哪些内容
- 将同一条录音中的不同说话人区分为 `Speaker A`、`Speaker B`、`Speaker C`、`Speaker D`
- 让系统根据检索结果总结一个问题的答案
- 点击答案中的引用片段，跳回对应录音时间点复听

## 3. MVP 范围

### 3.1 P0 核心功能

#### 1. 录音导入

- 支持单个或批量上传音频文件
- 支持基础音频格式，如 `mp3`、`m4a`、`wav`
- 录音导入后生成处理任务，并展示处理状态

验收标准：

- 用户可以在页面中完成音频上传
- 上传后能看到文件名、时长、上传时间、处理状态
- 失败任务可以看到失败状态

#### 2. 音频转写

- 后端异步调用语音转写能力，将录音转换为文本
- 保留时间戳信息，支持后续片段定位
- 保存完整转写结果和处理元数据

验收标准：

- 已上传录音可进入待处理、处理中、已完成、失败等状态
- 转写结果可持久化保存
- 每条转写内容能关联到音频和时间范围

#### 3. 文本分段与索引

- 将长文本按适合检索的方式切分为多个 chunk
- 建立全文检索索引
- 建立向量检索索引
- chunk 与音频时间戳保持映射关系
- chunk 保留说话人标签信息，支持基于说话人检索

验收标准：

- 每条录音可拆分为多个可检索片段
- 支持通过关键词和语义相似度检索相关片段
- 检索结果可回溯到原录音及时间点
- 检索结果可看到对应的说话人标签

#### 4. 自然语言搜索

- 提供统一搜索框，支持用户输入自然语言问题
- 系统根据问题进行检索，返回最相关的录音片段
- 检索结果列表展示命中的录音、时间范围、片段摘要或原文节选

验收标准：

- 用户输入问题后，能返回相关片段列表
- 列表至少展示录音标题、命中片段、时间点
- 支持进入录音详情查看上下文

#### 5. 基于检索结果的 AI 回答

- 使用命中的片段作为上下文，让大模型生成回答
- 回答必须基于检索结果，不允许脱离上下文自由发挥
- 回答中展示引用来源

验收标准：

- 用户针对问题可以获得简洁总结
- 回答附带引用的录音来源和时间点
- 用户能够区分“模型总结”与“原始片段”

#### 6. 录音详情与片段回放

- 展示录音基本信息、完整转写文本、分段片段
- 支持点击命中片段后跳转到对应音频时间点播放

验收标准：

- 用户可以查看整条录音的转写内容
- 用户可以从搜索结果跳转到对应片段
- 用户可以播放对应时间点附近的音频

#### 7. 说话人区分与标注

- 对单条录音内的不同说话人进行分离
- 在同一条录音内用稳定的匿名身份标注，如 `Speaker A`、`Speaker B`
- 在转写文本、片段列表、搜索结果中展示说话人标签

验收标准：

- 系统能够对多说话人录音输出分离后的说话人片段
- 同一说话人在单条录音内尽量保持统一标签
- 用户在录音详情页能看见每段话对应的说话人标签

#### 8. 目标人物识别

- 支持为某个已知人物录入参考音频样本
- 对录音中的说话片段进行比对，识别是否为目标人物
- 识别结果以“命中 / 未命中 / 低置信度待确认”的形式呈现

验收标准：

- 用户可为重点人物建立至少一个声纹参考样本
- 新录音处理后，系统可标出疑似目标人物出现的片段和时间点
- 目标人物识别结果可在录音详情和搜索结果中展示
- 低置信度结果不会被伪装成确定结论

### 3.2 P1 增强功能

以下能力建议放在 MVP 稳定后再纳入：

- 录音标题、标签、来源的手动编辑
- 搜索历史
- 最近访问录音
- 查询结果的二次追问
- 基于多条录音做主题总结
- 录音级摘要、关键词、人物提取
- 失败任务重试
- 多个已知人物的批量注册与管理
- 跨录音统一合并匿名说话人身份
- 用户手动修正某段说话人的标注结果

### 3.3 暂不纳入 MVP 的内容

- 实时录音与实时转写
- 复杂多 Agent 编排
- 多租户组织权限体系
- 精细化的角色与权限管理
- 本地离线推理和本地部署能力
- 完整的声纹画像系统和高级生物特征管理
- 移动端原生 App
- 企业级审计、计费、配额体系

## 4. 用户流程

### 4.1 首次导入流程

1. 在后台页面上传一个或多个录音文件
2. 系统创建转写任务
3. 系统完成转写、说话人分离、目标人物识别、分段、建索引
4. 用户在录音列表中看到可搜索状态

### 4.2 搜索问答流程

1. 用户输入自然语言问题
2. 系统执行混合检索，召回相关 chunk
3. 系统对结果重排并选取高相关上下文
4. 模型基于上下文生成总结答案
5. 页面展示答案、引用来源和命中片段
6. 页面展示命中片段对应的说话人标签和目标人物标记
7. 用户点击来源，跳转到录音详情或对应时间点

## 5. 页面级 MVP 清单

### 5.1 首页 / 工作台

- 上传录音入口
- 最近上传的录音列表
- 任务处理状态概览
- 全局搜索入口

### 5.2 录音列表页

- 展示所有录音
- 支持按状态筛选
- 支持按标题或文件名搜索

### 5.3 搜索结果页

- 搜索输入框
- AI 总结答案区域
- 命中片段列表
- 每个片段的来源与时间点
- 每个片段的说话人标签
- 目标人物命中标记

### 5.4 录音详情页

- 音频播放器
- 录音元数据
- 完整转写文本
- 分段导航
- 高亮命中片段
- 每段文本的说话人标签
- 目标人物出现片段的高亮标识

### 5.5 目标人物管理页

- 目标人物列表
- 参考音频样本上传入口
- 识别状态与最近命中记录

## 6. 非功能要求

### 6.1 可用性

- 上传和处理状态清晰可见
- 搜索响应时间尽量控制在可接受范围内
- 失败任务对用户可见，不静默失败

### 6.2 可信性

- AI 回答必须附引用
- 每个引用可追溯到原始文本和时间点
- 优先展示原始证据，再展示模型结论
- 目标人物识别必须展示置信度或待确认状态

### 6.3 可维护性

- 转写、切分、索引、检索、回答应按模块拆分
- 异步任务和在线查询链路分离
- 预留后续接入不同转写模型和向量模型的能力

## 7. MVP 验收标准

当以下目标满足时，可以认为 MVP 具备初步验证价值：

- 用户可以上传并管理一批历史录音
- 大部分录音可以完成自动转写并建立索引
- 系统可以区分单条录音中的多个说话人
- 系统可以识别重点目标人物是否出现在录音中
- 用户可以通过自然语言找到相关历史片段
- 系统可以给出基于证据的简要答案
- 用户可以从答案跳回原始录音片段复核

## 8. 成功指标建议

建议在 MVP 阶段跟踪以下指标：

- 转写成功率
- 说话人分离可用率
- 目标人物识别命中后的人工确认准确率
- 录音处理平均耗时
- 搜索命中率的主观反馈
- 用户点击引用回看的比例
- 用户重复使用搜索功能的频次
- 单次问答平均响应时间

## 9. 后续演进方向

- 从单次检索升级为多轮追问
- 从单录音问答升级为跨录音主题分析
- 加入查询改写、重排和混合召回优化
- 引入 LangGraph 管理更复杂的问答流程
- 增加标签、摘要、实体抽取等知识整理能力
- 从录音内 `Speaker A/B/C` 升级到跨录音的说话人身份归并
